# 4 — verification and sources

Open this reference before recommending any setting, runtime, or version
change. A value in a config file is a claim to verify, not a diagnosis.

- [setting ownership](#setting-ownership)
- [LOD distance rules](#lod-distance-rules)
- [shader setting rules](#shader-setting-rules)
- [Java and native rules](#java-and-native-rules)

## Setting ownership

For every setting you want to touch, establish:

1. **Owner:** Minecraft, loader, which mod, shader pack, or resource pack?
2. **Reader:** does the installed version actually read that key?
3. **File:** is this the file the running instance uses (right instance,
   right profile, not a stale export or another pack)?
4. **Status:** deprecated, ignored, overridden, generated by an older
   version, or only read on one screen/path?

State `verified` vs `inferred` for every runtime claim. Never invent config
paths or keys. Never label an unrelated value "OK" or "problematic" without
a version-specific reason or a measured target.

## LOD distance rules

A large LOD number is not "too high" by itself. Before judging it:

1. Read the exact mod version's semantics: units (chunks? blocks? regions?),
   what the radius measures from, defaults, documented range.
2. Relate it to measured cost: LOD CPU, RAM, GPU/streaming load, and the
   user's target experience — not to vanilla render-distance intuition,
   which uses a different coordinate model.
3. Change it only as one variable in a controlled test with a recapture.

Distant Horizons example (checked 2026-10-29): `lodChunkRenderDistanceRadius`
is documented in shipped `DistantHorizons.toml` comments as measured in
chunks; real-world configs vary widely across packs, so 256 is unusual but
not self-evidently wrong — verify version semantics and measured LOD cost
first. Do not generalize this example to other LOD mods or versions.

## Shader setting rules

1. Identify the active shader pack and its exact version first.
2. Determine which control is exposed by Iris and which is implemented by
   the pack itself. Iris renders what the pack declares; pack-defined
   constants live in the pack's GLSL/config.
3. A similarly named key in an Iris config file (e.g. a
   `maxShadowRenderDistance`-style key in `config/iris.properties`) does
   not control the pack's shadow distance until proven — confirm the actual
   source of the setting and the relevant render path before claiming it.

Reference (checked 2026-10-29): Iris documents `shadowDistance` as a
pack-side GLSL constant setting the shadow-pass radius in blocks, default
160 (`shaders.properties` shadowDistance reference). This is the pack's
domain, not an Iris `.properties` key — verify against the installed
Iris/pack versions before recommending a change.

## Java and native rules

1. Verify exact MC version, loader version, mod version,
   launcher-selected Java executable, and the mod release's declared
   runtime requirements — each one, not "Java 25 vs MC 1.21.1" from memory.
2. Out-of-tested-range is a compatibility risk, never automatic proof of
   causality.
3. A JNI `UnsatisfiedLinkError` proves a native binding/load mismatch. It
   does not by itself prove the Java major version caused it. Check the
   native method declaration, packaged native library (version/arch), the
   release's requirements, and reproducibility under a supported runtime —
   then state the root cause, or keep it a hypothesis with the test that
   settles it.

Distant Horizons example (checked 2026-10-29): DH 3.3.3 ships per-version
releases (e.g. `3.3.3-1.21.11` for MC 1.21.11 on Modrinth, published
Sep 2026) — match the installed MC/mod pair exactly, then check that
release's requirements and native packaging before attributing a
`NativeDB._open_utf8` failure to Java. Do not generalize across DH/MC pairs.

## Source hierarchy

For version-specific questions, prefer in this order and record what each
source proves (claim + version + date):

1. Installed artifact/config plus that exact version's shipped docs or
   source (strongest: what the running code reads).
2. Official project page, release notes, changelog, repo, issue tracker for
   the exact MC/loader/mod release.
3. Official Minecraft/loader/Java/launcher documentation.
4. Reputable technical discussion — secondary evidence only, never the sole
   basis for a causal claim.

Distinguish current-version docs from stale or similarly named versions:
check the doc's stated version range, release date, and URL path before
citing; a page for MC 1.20.1 proves nothing about 1.21.1. A closed issue is
not a fix — read the resolution and affected versions. Never cite a homepage
as proof of a specific behavior. Re-check transient facts (release lists,
compat matrices, download pages) at analysis time; never freeze them as
permanent truths in a diagnosis.

## Research order and citations

Prefer, in order:

1. Installed artifact/config plus that exact version's docs or source.
2. Official project page, release notes, changelog, repository, issue
   tracker for the exact version.
3. Official Minecraft/loader/Java/launcher documentation.
4. Reputable technical discussion only as secondary evidence.

Per source record: URL, version/date, and the exact claim it supports. The
source must match the game version and release in use. Never cite a
homepage as proof of a specific behavior. A closed issue is not a fix —
read the resolution and affected versions.

Starting points (verify relevance to the exact version under
investigation): Spark docs https://spark.lucko.me/docs/ and source
https://github.com/lucko/spark (profiler flags incl. `--thread`,
`--interval` default 4 ms, `/sparkc` on Forge/Fabric clients, per current
Command Usage page); Loading Profiler
https://modrinth.com/mod/loading-profiler; VisualVM
https://visualvm.github.io/features.html; JFR/JMC Oracle docs
https://docs.oracle.com/en/java/java-components/jdk-mission-control/9/user-guide/using-jdk-flight-recorder.html
and https://dev.java/learn/jvm/jfr/getting-started/; `jcmd` reference
https://docs.oracle.com/en/java/javase/21/docs/specs/man/jcmd.html; OpenJDK
JFR JEP https://openjdk.org/jeps/328; async-profiler
https://github.com/async-profiler/async-profiler; Prism Launcher
https://prismlauncher.org/wiki/ (`$INST_DIR`, `$INST_MC_DIR`, `$INST_JAVA`
custom-command variables; the launched Java may differ from shell `java`);
Agent Skills format https://agentskills.io/ (folder with `SKILL.md`,
frontmatter `name` + `description`, progressive disclosure).
